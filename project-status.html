Why 9% when the site looks finished? Every public section has been rebuilt to its final design — including skeleton loading states — but they all still read from translations.js and placeholder files rather than from Sheets or Drive. The goal is a site the committee can edit without a developer — none of that exists yet. Phase 1 is what converts the blue bar into the green one.

Committee Fund → Transactions the gated flow

How a committee member reaches the Transactions page

  1. The public page ends with a single Committee Fund button — no table, no figures, and deliberately not in the nav.
  2. Clicking it opens a modal asking for Mobile Number and Secret Code (circulated privately, rotatable from the Admin Portal).
  3. Both values are posted to the Auth Web App. Verification happens inside Apps Script — the browser never holds the code list.
  4. The script checks the mobile exists in the committee sheet and the code matches settings, then returns a short-lived session token.
  5. On success the app routes to /transactions — the ledger with running totals, year filter, PDF export and a Back button.
  6. The session expires on inactivity and on refresh, so a shared link alone opens nothing.

Non-negotiable: the secret code must never be compared in React. Anything shipped to the browser — including .env values — is readable in the built bundle. The comparison belongs in the Apps Script Web App only, with failed attempts rate-limited.
