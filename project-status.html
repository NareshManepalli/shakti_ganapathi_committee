Committee Fund → Transactions the gated flow

How a committee member reaches the Transactions page

  1. Visitor scrolls to the end of the public page and sees a single Committee Fund button — no table, no figures, nothing exposed.
  2. Clicking it opens a modal asking for Mobile Number and Secret Code (the code is circulated to committee members privately and can be rotated from the Admin Portal).
  3. Both values are posted to the Auth Web App. Verification happens entirely inside Apps Script — the browser never holds the code list.
  4. The script checks the mobile number exists in the committee sheet and the code matches the current value in settings, then returns a short-lived session token.
  5. On success the app routes to /transactions — the full ledger with Cash In / Cash Out / Balance, running totals, year filter, PDF export and a Back button to the public site.
  6. The session expires after inactivity and on refresh; the route is unreachable without a valid token, so a shared link alone opens nothing.

Non-negotiable: the secret code must never be compared in React. Anything shipped to the browser — including .env values — is readable in the bundle. The comparison belongs in the Apps Script Web App only, and failed attempts should be rate-limited to stop code guessing.
