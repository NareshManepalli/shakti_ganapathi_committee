Committee Fund → Transactions the gated flow

How a committee member signs in

Changed 07 Aug 2026. The shared secret code is gone. A member now proves who they are with a one-time code emailed to the address held against them in the members sheet — nothing to circulate, nothing to rotate, and a leaked code is worth 5 minutes.

  1. The public page ends with a quiet logo + committee name card under Mandapam Location — no figures, and deliberately not in the nav.
  2. Clicking it opens /funds: emblem, committee name, Committee Funds, the line only committee members are allowed to view this area, a mobile field and a 4-digit captcha.
  3. Verify & Send OTP checks the captcha in the browser first — a wrong one costs no lookup and no email, and the captcha is regenerated so it cannot be brute-forced.
  4. The mobile goes to the Auth Web App, which reads the members sheet with SpreadsheetApp and answers in order: not on the list → not a member; access_in = 0 → no permission to sign in, decided before any mail is sent; no email on the row → says so.
  5. Otherwise it generates a 6-digit code, holds it for 5 minutes in CacheService, and emails it. The code never reaches the browser — the reply carries only the member's name and a masked address.
  6. /funds/verify greets them by name with 🤝, shows where the mail went, and offers six boxes. Two clocks run: 5 minutes of validity and 1 minute until Resend OTP unlocks.
  7. A correct code returns an HMAC-signed token carrying the member id and adm_in. adm_in = 1 opens every screen; adm_in = 0 opens Transactions and Monthly funds only.
  8. The session lives in sessionStorage for 60 minutes and dies with the tab, so a shared link alone opens nothing.

Non-negotiable: none of this may be decided in React. The code is generated, stored, emailed and compared inside Apps Script; the token is signed with a key in Script Properties. Anything shipped to the browser is readable in the built bundle. The captcha is the one browser-side check, and it is a speed bump, not a lock — the real limits are server-side: 1 minute between sends, 5 an hour, 5 wrong codes and the code is burned.
