What's left the launch list, and the tests that guard it

Tests are kept until development is complete

They earn it. Each of these looked fine in a browser and was found only by a test: a statement button that reset silently and produced no file at all; an entry drawer whose fields vanished the moment a date was typed; screens asserted as loaded while still grey, because the placeholder table matched the selector waiting for the real one. None of them showed up in a build.

The cost is that a spec goes stale whenever the screen it watches changes — renaming photos to files, retiring Settings, adding two fields ahead of a third. Rows are found by their accessible names now rather than by counting, which is what kept breaking.

Run before each deploy: npx playwright test. --project=stubbed --project=docs needs nothing and runs 66 specs in under two minutes. The rest hit the live services and need a member with bypass_in = 1 in tests/.local.json, gitignored because this repository is public.

All pass. Two of them write to the President's real row and put it back — and the undo is now checked against the server rather than assumed, because a run that assumed it left "Venkat Naresh QA" as the name on the live public site. If the screen fails to restore, the spec repairs the record directly and still fails, so the data is never the thing that pays for a broken test.

The live funds specs sweep before and after themselves, through the Web App rather than the screen, so a run killed part way — a timeout, a lost answer, Ctrl-C — cannot leave a "Playwright check" row in the committee's ledger. Enough of those accumulated once to put the balance out by 1,500 rupees for a fortnight before anyone looked. Proved by stranding a row deliberately and watching the next run take it out.

A member with bypass_in = 1 signs the suite in through the fixed code directly, rather than asking the gate to email one. The throttle is on sending — one a minute, five an hour — and it interrupted these runs repeatedly, always reporting itself as "Sign-in is not set up yet", which sends whoever is reading off to check a configuration that is perfectly fine. The full sign-in still runs for a member without the flag, since it is the only thing that exercises the captcha and the OTP screen.
